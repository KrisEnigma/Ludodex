# Ludodex audit, 30 Sep 2026 (revision 2)

## Context

Ludodex is **pre-launch** work in progress that has been paused. Several things are placeholders, so this audit doesn't treat them as defects:

- dates (`LAUNCH_DATE`);
- the demo puzzles;
- the fonts;
- monetization, which is boilerplate with no ad or purchase setup finished yet.

Several gameplay choices are **deliberate**, and this audit treats them as fixed design:

- no feedback on a wrong selection;
- long-press hints;
- a spoiler-free share card, where there's no "correct" order to find the words in;
- a chain that stays lit after a non-word release;
- strict mistake counting that is revealed only on the win screen.

## How I reviewed it

- Read the whole repo.
- Ran `tsc --noEmit` and `vite build`; both were clean.
- Queried the live API.
- Played the game on the local dev server at 390×844.
- Screenshotted every screen.
- Cycled through 12 skins using the real `applySkin()`.

I checked every `file:line` reference on this date. Anything marked **unverified** I couldn't confirm.

---

## TL;DR

The code foundations are good. The input state machine, the token-based skin system, the remote → cache → bundle loader and the anti-spoiler DOM handling all show care. For when you pick it back up, the work splits into three buckets:

1. **Real bugs** that exist regardless of stage. There are a handful, and they're mostly small (§1).
2. **Visual identity.** This is the biggest lever. The game is tidy but plain, there's a lot of dead space, and the 33 skins are nearly all palette and font swaps on one layout. See §2.
3. **Hardening before launch:**
   - make the content pipeline safe (one bad save can blank the app);
   - fix the specific defects in the ad and in-app purchase (IAP) boilerplate before wiring it;
   - swap in fonts licensed for commercial use and rename trademarked skins;
   - add an `og-image`.

   See §3.

## 1. Real bugs (fix regardless of stage)

| # | Bug | Where | Fix |
|---|---|---|---|
| 1 | **Hints don't work with Reduce Motion on.** The reveal fires only on the `animationend` of `hint-reveal-rise`, and the reduced-motion CSS removes that animation. Long-press does nothing on iOS "Reduce Motion" or Android "Remove animations". | `GameView.ts:430`, `index.css:1316` | Keep the long press, but time it with a JS timer (`setTimeout` on pointerdown, cleared on up, leave or cancel). The CSS then only decorates. |
| 2 | **Holding a slot that's already filled by a solved word spends a hint** (and costs the 3rd star). The guard only checks `revealed`, not `filled`. | `GameView.ts:436` | Return early if `slot.dataset.filled === 'true'` or `solvedPartIds.has(meta.partId)`. |
| 3 | **Modal Enter confirms destructive actions even when Cancel is focused** (Reset progress, Leave puzzle). | `Modal.ts:120` | Remove the global Enter handler; focused buttons handle Enter natively. |
| 4 | **Daylight-saving time (DST) drift in the day number.** `Math.floor` over local midnights repeats or skips a day across DST changes. I verified this with southern-hemisphere timezones. | `PuzzleLoader.ts:324` | Use `Math.round`, which `ProgressService` already does. |
| 5 | **The build script swallows failures.** `A && B \|\| true && C && D` means a failed puzzle sync is ignored. | `package.json:9` | `(node scripts/check-creator-drift.mjs \|\| true)` in its own group. |
| 6 | **Achievement locks bypassed.** `productId === null → true` runs before the achievement check, so Terminal (solve_50) and Phosphor (pristine_10) are free on native. | `IAPService.ts:170` | Check `unlockedByAchievement` first. |
| 7 | **Views never clean up.** The `resize` listener is never removed. Timer and listeners leak when a view is replaced via `popstate` or a deep link. | `GameView.ts:385`, `Router.ts` | Add `dispose()` and an `AbortController` per view, called from `Router.mount`. |
| 8 | **Android Back leaves sheets floating.** Sheets are appended to `body`, and web history uses `replaceState` only, so browser Back leaves the site mid-puzzle. | `Router.ts:159-209` | Add a router overlay stack plus `pushState`. |
| 9 | **The disabled Play button looks enabled** (opacity 1, pointer cursor; verified in the DOM). | `MenuView.ts:160` + CSS | Style `button:disabled`. |
| 10 | **PurgeCSS is silently off.** `require(...).default` is `undefined` in v8, so the plugin never loads. That's lucky: its `greedy: [/\[data-/]` safelist matches nothing (tested), so turning it on would strip `.tile[data-state="selected"]`, the endgame phases and more. | `postcss.config.cjs` | Delete PurgeCSS and its guardrail note. It would only save about 19 KB. |
| 11 | **Hardcoded English** ("Using hint…", "Changing icon...", `unlockHint`s), and `<html lang>` never changes. | `GameView.ts:227`, `SettingsView.ts:566` | Translate them, and set `documentElement.lang` in `setLang`. |

## 2. Visual design and UX

### 2.1 What I saw

| Screen | Works | Could be better |
|---|---|---|
| **Boot** | – | About 1–2 s of blank dark screen. `loadPuzzles` waits up to 1.8 s for the network, and there's no HTML splash. |
| **Tutorial** | Clean icons; the "LUDO" swipe graphic is a nice idea. | Static slides; the bottom 40% is empty. The copy "Release when it's complete" is inaccurate, because words auto-submit. |
| **Menu** | Clear stat trio; strong daily card. | **The bottom 45% of the screen is empty.** The wordmark is small and doesn't move. |
| **Game** | Big legible grid; slot groups for multi-word answers; dimmed solved tiles; lovely flash wave along the path. | **The bottom ~30% is empty** and the grid sits high. Hint slots are about 22×30 px, which is a small target for a long press. The ribbon changes colour in visible steps (violet→cyan) and cuts through the middle of each letter. |
| **Win** | Stars, big time, achievement cards; the glitch uses skin colours. | "4 mistakes" is small grey text with no explanation of what counts. The Get-the-App CTA is below the fold on the web. |
| **Settings → Skins** | The **detail sheet preview** (full board plus ribbon) is the best skin UI in the app. | The picker hides it behind 33 near-identical dark cards, each showing two tiny tiles. The card doesn't show the skin's background, font or overall look, so they're hard to tell apart. |
| **Achievements** | Clear 3/39 count and categories. | A text list with padlocks: no badge art and no per-achievement progress. |
| **Archive** | Simple, and shows your stars. | A plain list: no dates, calendar or completion pattern. |

### 2.2 Game feel within the "reward finds only" design

Everything here adds reward to finds or polish to selection. None of it gives feedback on wrongness.

1. **Audio for finds and the win only.** A small Web Audio synth, with no files to ship:
   - a short chord plus a coin blip when a word is found;
   - a brighter variant for the last word;
   - a 4-note jingle on the win screen, with a richer version for 3★;
   - a very soft constant-pitch tick per added tile (decided later; carries no right/wrong signal);
   - a mute toggle, and respect for the device's silent switch on native.

   Each skin can give it a different sound later (§2.4).
2. **Make finds land harder:**
   - after the flash wave, fly the letters from the grid into their slots (FLIP animation, ~350 ms, staggered), which visually connects the two halves of the screen;
   - a small "2 / 3" counter pop;
   - a stronger haptic on the final word.
3. **Ribbon polish** (visual only):
   - one polyline with a single `userSpaceOnUse` gradient, so the colour blends smoothly instead of stepping per segment;
   - rounded joins;
   - a subtle plate behind the selected glyph, so the ribbon doesn't cut through the letter;
   - optionally, a tail segment from the last tile to the finger.
4. **Win-screen clarity:**
   - put the mistake count next to the stars, with a one-line key ("3★ = no hints, no mistakes");
   - list the answers you found (this is your own screen, so it doesn't spoil anything for others).

### 2.3 Layout and composition

- **Grid:** centre it vertically in the available space. Or use the lower third for larger hint slots (≥ 32 px). Larger slots are easier to long-press deliberately and fit the "no accidental use" intent even better. Plus a found-words tray.
- **Menu:** fill the empty half. Pick from:
  - (a) a larger animated wordmark in the skin's display font;
  - (b) a 7-day streak strip (reuse the tutorial graphic, which already looks good);
  - (c) ~~a teaser of today's board as a 4×4 of blank tiles in the current skin, which doubles as a skin preview;~~ tried and dropped (Oct 1 2026): added nothing;
  - (d) ~~yesterday's answers behind a tap-to-reveal.~~ Skipped (Oct 1 2026): spoils a puzzle that stays playable.
  - Done: (a) wordmark sweep, (b) 7-day streak strip.
- **Boot:** put an inline wordmark splash in `index.html`. Render from cache or the bundle first, then refresh in the background, instead of waiting up to 1.8 s.
- **Web hint store:** buy buttons can't work on the web (`purchase()` returns `unavailable`). Show a "Get more hints in the app" card instead.

### 2.4 Skins: fewer, deeper

**Diagnosis:**
- A skin controls 11 colour tokens, fonts, radius, glow and ribbon width. Only Aero and Mushroom Kingdom have any bespoke CSS, and the background is always a 2-stop radial gradient.
- **Near-duplicates:**
  - Terminal, Phosphor and BIOS are one skin in three hues.
  - Neon Horizon, Swarm and Laser Vector all use Orbitron on dark.
  - Crimson, Phantom Thieves, Rip & Tear and Dragon Heat are all red on black.
  - Lord of Terror and Blood & Darkness are both Cinzel with gold.
  - Dot Matrix, Maze Chase and Toaster all use Press Start 2P with square tiles.
- The strongest skins in the screenshots were Mushroom Kingdom (bold orange on flat blue), Aero (glass), Lord of Terror (atmospheric) and Dot Matrix. They're the ones with a *concept*, not just a colour change.

**Recommendations:**
1. **Cut to about 12 hero skins, and fold the rest into palette variants.** For example, "CRT" becomes one skin with Amber, Green and Blue options in its detail sheet.
2. **Add five optional skin layers.** Each comes from a small shared library, so you build each effect once and every skin can use it:

   | Layer | Mechanism | Examples |
   |---|---|---|
   | Backdrop | `--bg-layer` on `.app::before` (SVG data-URI patterns plus optional slow motion, off under reduced motion) | scanlines + vignette, LCD pixel grid, starfield drift, halftone, graffiti wall, aurora |
   | Tile material | `data-tile="flat \| glass \| bevel \| pixel \| plate"` via box-shadow stacks, `clip-path` or masks (never transform, z-index or isolation on `.tile`) | stepped 8-bit borders, "?-block" bevel, glass |
   | Ribbon | `data-ribbon="neon \| pixel \| chalk \| dashed \| lightning"` | pixel skins get a stepped square-cap ribbon; Radio Tag gets a spray stroke |
   | Find FX | `data-fx-found="flash \| pixel-burst \| coin-pop \| ink-splat \| glitch"` | flash stays the default |
   | Endgame FX | `data-fx-end="crt \| shatter \| iris \| fade"` | the CRT glitch suits Terminal but not Aero or Dream Spiral |

   Plus a **sound preset** per skin for the find and win sounds: a square wave for 8-bit skins, bells for Aero, a detuned saw for synthwave.
3. **Build the picker around the detail sheet:**
   - Use mini screen cards: the skin's real background, a 2×2 tile patch with a ribbon, and the name in the skin's wordmark font.
   - Group them into collections.
   - Show unlock progress on locked skins ("12/30 🔥").
   - Revive the dead full-screen live preview (`SettingsView.ts:43-85`). The README already promises it.
4. **Replace the cascade shield.** Declare the derived variables on `:root, .skin-scope`, and put `skin-scope skin-<id>` on both `<html>` and each preview wrapper. That removes about 1,300 repeated literal declarations and both `@scope` blocks.
5. **Contrast** (my approximate calculations from the tokens): Blue Blur dim text is about 1.7:1; Aero white on `--action` is about 1.8:1; Radio Tag tile letters are about 2.9:1. Add a contrast check to `check-creator-drift.mjs`.

### 2.5 Share: spoiler-free visual card

Keep the rules: no letters, no paths and no order, since everyone plays the same grid. What *can* be shown safely:
- **An image card in the player's current skin:** title, day number, stars, time, hints used and streak, over the skin's backdrop and wordmark.
  - It contains no grid information.
  - Share it via `@capacitor/share` as a file, keeping the text as a fallback.
  - Every share then advertises a skin, which is the best marketing a paid skin can get.
- Fix `og:image`: `/og-image.png` doesn't exist, so the live URL falls back to the app's HTML page and link previews break.

### 2.6 Other screens

- **Achievements:** simple badge art in the skin's display font (hexagon + glyph + tier colour), progress bars on streaks and counts, and an "almost there" row at the top.
- **Archive:** a month calendar with days coloured by stars, or at least dates.
- **Tutorial:** optionally a playable 2×2 practice board (the `isTutorial` flag exists but is never set). At minimum, fix the "release when complete" copy.

### 2.7 Accessibility

Beyond bugs 1 and 11:
- **Keyboard play:** type a letter to pick an adjacent matching tile; Backspace undoes; Esc clears.
- **Screen readers:** add `role="grid"`/`gridcell` with `aria-selected`. Add a polite live region that announces **only found words** ("Found MARIO, 2 of 3"), which fits the rewards-only design.
- **Modals:** add focus trap and focus restore to the sheets.
- **Hints:** a long-press hint could have a keyboard equivalent, such as focusing the slot and holding Space.

## 3. Hardening before launch

### 3.1 Content pipeline (the demo puzzles themselves aren't audited)

**Positional schedule.** The daily is `puzzles[dayNumber-1]`, and it returns `null` once the catalog is exhausted (`PuzzleLoader.ts:283`). After launch:
- Adding puzzles when you're behind the calendar fills the archive, not today.
- Streaks break for everyone on the first missing day.
- The notification still fires.

Before launch, choose one of:
- (a) a runway check in CI (fail if fewer than N days are ahead), plus a rerun fallback (`puzzles[(day-1) % n]`, labelled "Rerun");
- (b) an explicit `date → puzzleId` schedule written by the editor.

Either way, skip the notification on days with no puzzle.

**Editor → production is unguarded:**
- New levels are PUT immediately with `data: {}`.
- `saveGrid()` saves even when validation fails.
- Reordering changes which puzzle belongs to which past day.
- The Worker (`src/index.ts:149`) accepts any non-empty array, with no schema, no size cap, no `If-Match` and no backup.

**How a bad save ends in a blank screen:**
1. `sync-puzzles` copies production into the bundle without validating it.
2. So one malformed puzzle breaks both the remote copy and the fallback.
3. `loadPuzzles` throws inside the startup code, and nothing renders.

**Fixes:**
- Validate on the server with the client parser.
- Snapshot to `puzzles/<iso>.json` before each put.
- Separate draft from published.
- On the client, skip individual bad puzzles.
- Run `validate:puzzles` in `build`.

**Validator gaps** (worth adding now, since they'll catch authoring mistakes later):
- coordinate format `[a-d][1-4]` (`PuzzleCodec` checks this, but `parsePuzzle` doesn't);
- a single word's own path visiting the same tile twice (e.g. `a1 b2 a1`), which can't be entered because stepping onto a tile already in the chain backtracks. Tiles *shared between different words* (GWYN / GWYNDOLIN) are normal and fine;
- missing `es` name or hint.

Prefix answers such as GWYN/GWYNDOLIN are fine as designed ("first word found wins"; see §6).

**Freeze puzzle ids once they're public.** `.wrangler` has `videogameheroes` while production has `video-game-heroes`, and a rename orphans players' solve records.

### 3.2 Fonts and names

- **Fonts to replace before shipping** (unless you get a commercial licence). DooM.ttf's name table says "not for comercial use!!"; the others:
  - `diablo.woff` (© MaGiK Software);
  - AmazDooM (© ParaGraph);
  - `SuperMarioBrosWii.otf`;
  - `SNES Italic.ttf`.
- **Trademarked skin names:** "Hyrule Vault", "Mushroom Kingdom", "Cyber Shinobi" (a real Sega title), "Phantom Thieves", the `gameboy` id and product id, and the "Tristram is calling" copy. Apple guideline 5.2 applies, and it's worst on paid skins. Generic, evocative names like "Toaster" and "Dot Matrix" already work well.

### 3.3 Defects in the monetization boilerplate (fix when wiring)

**Ads:**
- `initAds()` has no caller. Until it does, hide the "Watch ad" button and the "Remove Ads" copy behind a feature flag, so they don't ship half-working.
- `AdService.ts:293`: `result.type === RewardAdPluginEvents.Rewarded` compares a reward type with an event name, so it is always false. Treat a resolved `showRewardVideoAd()` as the reward, or listen for the `Rewarded` event.
- Both manifests use Google's test app IDs.
- iOS is missing `NSUserTrackingUsageDescription` (the ATT request crashes without it) and `SKAdNetworkItems`.
- Set up the UMP consent flow for the EU.

**IAP:**
- `ios/App/CapApp-SPM/Package.swift` has no RevenueCat and no Sentry. The pinned versions only ship CocoaPods specs, so they don't link under Capacitor 8's Swift Package Manager (SPM) setup. RevenueCat 9.2.2 also declares a peer of `@capacitor/core ^6`. Upgrade both.
- Env var names: `IAPService.ts:130` reads `VITE_RC_IOS_KEY`/`VITE_RC_ANDROID_KEY`, but `.env.example` documents `VITE_REVENUECAT_API_KEY`. The fallback is the literal `'RC_KEY'`; fail loudly instead.
- Buy path: the Buy button only renders when `productId && !unlockHint` (`SettingsView.ts:221`), but every paid skin has an `unlockHint`. The price is hardcoded to `$0.99`, and `skin_mushroom_kingdom` is missing from `PRODUCT_IDS`.
- Purchased hints are local-only and wiped by "Reset progress" (`ProgressService.ts:492`).
- There's no handling for purchases that complete outside the normal flow (for example Ask to Buy, or pending Android purchases).

**Native:**
- **iOS:**
  - no `PrivacyInfo.xcprivacy`;
  - no Associated Domains entitlement;
  - a stale `armv7` capability;
  - landscape is allowed, while Android is portrait-only.
- **Android:**
  - `assetlinks.json` still has a placeholder;
  - `versionCode 1`, with minify off;
  - a stale `app/glitchsalad` MainActivity.
- **Unverified on device:** `AlternateIconPlugin.java:53-57` disables `MainActivity`, which holds the App Links intent filter, so choosing an alternate icon may break deep links.

### 3.4 Backend and security

- **The editor** is served publicly on the game's origin, with its token in `localStorage` (`editor.js:117`). The API sends `Access-Control-Allow-Origin: *` on PUT and DELETE, and the token comparison isn't constant-time. `public/` also copies the editor into the native builds.
  - Fix: move it behind Cloudflare Access on a subdomain; allow CORS for GET only; use `crypto.subtle.timingSafeEqual`; exclude it from `cap sync`.
- **`functions/api/puzzles.js` is dead.** `wrangler.toml` deploys the `src/index.ts` Worker instead.
- `run_worker_first = ["/*"]` bills a Worker call for every asset. Limit it to `/api/*`, `/editor*`, `/privacy` and `/terms`.
- **Clean:** there are no secrets anywhere in git history, and the Worker refuses writes when `API_SECRET` is unset.

### 3.5 Engineering hygiene

- **Hit-testing** makes about 33 `getBoundingClientRect` calls per pointermove, and each ribbon segment has a `drop-shadow` filter. Cache tile centres on pointerdown and in a `ResizeObserver`.
- **Fonts:** about 35 `@fontsource` families are imported eagerly, each with woff *and* woff2 (about 550 KB of redundant woff). Use woff2 only, and lazy-load fonts for skins that aren't active.
- **Duplication:**
  - the time formatter appears 4 times;
  - the star renderer 4 times;
  - the top bar 3 times;
  - there are 4 hand-built bottom sheets.

  Extract `utils/format.ts` and a `BottomSheet` component.
- **Tests:** there are none. Add Vitest for the parts that cost players their streaks: day math across timezones, streak and freeze, hint grants, the parser and codec, and the Worker.
- **Stale docs:** the README describes 5 skins, including "Synthwave", and its star table doesn't match `getStarRating` (`GameView.ts:1160`: mistakes but no hints gives 2★). The handoff doc says there are 50 bundled puzzles.

## 6. Gameplay decisions (resolved with Kris)

### 6.1 Prefix answers: first word found wins
This works as intended, and I checked GWYNDOLIN is still reachable:
- In tap mode, G-W-Y-N submits GWYN (`InputManager.ts:233`).
- After that, `findPartMatch` skips solved answers (`GameView.ts:843-848`), so tapping the same four letters again doesn't match. The chain stays open and you can carry on to GWYNDOLIN.
- Swipe mode waits mid-swipe but still submits GWYN if you release there (`GameView.ts:766`).

Both modes follow the rule. Nothing to change.

**Update (Oct 1 2026, Kris):** swipe mode no longer waits either. A swipe finds an answer the moment it spells it and ends there, even if a longer answer starts with it. GWYNDOLIN is then its own swipe, passing the solved GWYN without matching it. `isLongerPrefixPossible` was removed.

**Update (Oct 1 2026, Kris):** swipe mode no longer waits. A swipe finds an answer the moment it spells it; if a longer answer still starts with the chain (GWYN → GWYNDOLIN), the swipe stays alive so you can carry straight on (`onWordFound(..., { keepChain })`).

### 6.2 Best time, "NEW BEST" and speed achievements

**What the code does today:**
- `solvedTimes[puzzleId]` keeps the fastest time **including replays** (`ProgressService.ts:369-371`).
- The menu's BEST is the minimum across all puzzles (`getBestTimeSec`, `ProgressService.ts:257`).
- The "NEW BEST" pill compares this solve against that global minimum (`GameView.ts:1200-1203`).
- `speed_60/30/20/15/10` and `pristine_lightning` check `elapsedSeconds` on **every** non-tutorial solve, replays included (`achievements.ts:80-84`, called from `GameView.ts:1227`). The retroactive check also uses the replay-inflated `bestTimeSec`.
- The timer starts when the game view is built (`GameView.ts:383`), so reading the title and hint counts towards the time.

**Problems this creates:**
1. **Replays collapse the whole speed tier into one minute.**
   - Solve a puzzle, tap Play Again, and re-swipe answers you just saw: you get Sub-10, Pristine Lightning and a "NEW BEST" together.
   - Five achievements that look like skill become a single replay.
   - This is the only achievement category that both counts replays and is presented as skill:
     - Pristine counts are already first-time-only (`ProgressService.ts:427`).
     - Volume uses unique solves (`solvedSet.size`).
     - Archive counts replays, but its comment says that's deliberate "engagement".
2. **Board size varies a lot.** Even with the demo set: Video Game Heroes is 19 answer letters, Chess Pieces 25, Solar System 35.
   - A global BEST, and absolute thresholds like Sub-30, reward whichever small board you happened to get.
   - The best speedrun strategy is to dig through the archive for the smallest puzzle.
3. **Per-puzzle best on its own isn't a fix.** A per-puzzle best only changes on a replay, and a replay mostly measures memory.

**Options:**

| Option | What changes | Pros | Cons |
|---|---|---|---|
| **A. First-play records** *(recommended)* | New key `ludodex.first_solve_times`, written only when `wasNewlySolved`. Menu BEST, the NEW BEST pill, `speed_*`, `pristine_lightning` and the retroactive check read from it. Replays still update `solvedTimes` for a per-puzzle replay best. | Records mean "solved it cold". Stops the farming. About 30 lines. Nothing to migrate, since nothing has launched. | A global BEST still mixes board sizes. |
| **B. Daily-only speed** | Speed achievements count only on today's daily, first play. | Everyone plays the same board that day, so times are comparable between friends and match what the share card shows. | Archive first-plays never count; fewer chances to earn. |
| **C. Pace** (s per answer letter) | BEST becomes "Best pace 1.8 s/letter", and the achievements become pace tiers. | Fair across board sizes. | Less intuitive than "Sub-60", and harder to share. |
| **D. Per-puzzle only** | Remove the global BEST. | Simple. | Measures memory; loses the headline stat. |

**Recommendation: A, plus replay feedback, plus recalibrating the tiers.**
- **On a first play:**
  - "NEW BEST" shows only when you beat your first-play record.
  - Speed achievements are checked against first plays only.
- **On a replay:**
  - No pill (decided: a "replay best" pill was tried and dropped; it isn't a convention players know).
  - No achievements from replays.
- **Archive rows:** show "First 1:12 · Best 0:41".
- **Recalibrate the tiers once there's data.**
  - Without replays, Sub-15 and Sub-10 on a first play may be close to impossible: reading the theme plus finding 3–6 words in 10 s.
  - `puzzle_solved` already logs `elapsed_sec` and `is_archive`; add `is_first_play`, then set the tiers around first-play percentiles (for example the 50th, 25th, 10th, 3rd and 1st).
  - If board sizes vary a lot in the real catalog, consider option C's pace just for the top two tiers, and keep plain seconds for the headline stat.
- **Timer and first-play rules (decided):**
  - **The timer starts when the board appears and never stops until the solve.** Looking at the board is playing, and a timer that never pauses is the only one a screenshot can't beat.
  - **No resume.** Leaving a puzzle means starting over.
  - **First-play status is lost by going back to the menu, closing the app, or restarting.** Backgrounding, a phone call, a notification or the hint store keep it.
  - **No in-game restart (checked, and none needed).**
    - The only restart-like actions are "Play again" on the win screen (`WinView.ts:187-192`) and "✓ Solved · Play again" on the menu. Both happen after a solve, so first-play status is already used up.
    - Mid-puzzle, going back to the menu *is* the restart, and it already loses first-play status.
    - A dedicated button would mainly let players reset a bad start on the timer, which is exactly what first-play records shouldn't allow.
    - Clearing a messy selection is already covered by tapping outside the grid.
    - If you ever add one, route it through the same "lose first-play" path as Leave.
  - **Revealed hints survive a leave or restart.** They're stored per puzzle (`addPuzzleReveal`, `GameView.ts:530`) and restored with `hintsUsed` on re-entry (`GameView.ts:558-588`). So leaving neither refunds a paid hint nor clears the hint star penalty. That's consistent with these rules, so keep it.

  **Why these rules have to go together:** with a timer that pauses, the screenshot trick simply moves from "leave" to "background":
  1. Screenshot the board.
  2. Switch to Photos. The app is backgrounded and the timer pauses (`GameView.ts:633-638`).
  3. Study the image for as long as you like.
  4. Come back and solve it in seconds, still as a first play.

  Keeping the clock running closes that gap. The only players who pay are ones genuinely interrupted mid-puzzle, and they lose only a speed time. Their solve, streak and stars are unaffected. For puzzles that last seconds to a couple of minutes, that's a fair trade.

  **Implementation (small; the timer is already based on `Date.now()`):**
  1. **Remove the pause:** delete `pauseTimer`/`resumeTimer` and the `visibilitychange`/`blur`/`focus` listeners (`GameView.ts:596-598, 611-646`). `getElapsedSeconds` becomes `Date.now() - timerStartedAt`. Keep the 100 ms interval for display only, since it catches up automatically when the app comes back.
  2. **Start when the board is visible:** start the clock after `view-entering` is removed, not in the constructor (`GameView.ts:383`, `Router.ts:44-48`). That's about 0.2 s, but it's 2% of a Sub-10.
  3. **Clock safety:** if `Date.now()` goes *backwards* mid-puzzle (a manual clock change), clamp the elapsed time to the last displayed value so it can't shrink. It can still jump forward, which is fine because it only hurts the cheater.
  4. **First-play tracking** (feeds the first-play records above):
     - When the board appears, write `ludodex.attempt = { puzzleId, startedAt }`, unless the puzzle is already solved or `firstPlayLost` is already set for it.
     - On a solve, clear the marker. If there's no `firstPlayLost` for this puzzle, it's a first play.
     - When the player confirms Leave → menu, add the puzzle to `firstPlayLost` and clear the marker.
     - On a cold start, if a marker is left over for an unsolved puzzle, the app was closed mid-attempt: add it to `firstPlayLost`.
     - Backgrounding touches nothing.
  5. **Edge case to accept:** iOS and Android sometimes kill a backgrounded app to free memory. That looks exactly like the player closing it, so a player whose phone killed the app during a long call loses first-play status on that puzzle. There's no reliable way to tell the two apart. It's rare for short puzzles, and it only costs speed records.
  6. **Hint purchases:** time spent in the native purchase sheet mid-puzzle counts. That's consistent (the board is still in play), and using a hint already costs the 3rd star.
  7. **Copy:** the Leave dialog could say "Leaving now restarts the puzzle and it won't count as a first try for records," so the rule is visible rather than a hidden penalty.

### 6.3 Tap vs swipe: the 12 px threshold

It's deliberate, and it's mostly fine: at normal swipe speed, 12 px goes by in about one frame. But I found an easy improvement that keeps the tap/swipe split:
- In `onPointerDown`, three of the five pending actions **produce the same chain whether the gesture turns out to be a tap or a swipe:**
  - `add` (empty chain, or an adjacent tile);
  - `new_chain` (a non-adjacent tile);
  - `clear` (outside the grid, or on a deactivated tile).

  See `InputManager.ts:70-104` and `applyPendingAction` (`:180-210`). The only difference between tap and swipe for these is that a tap also runs `attemptSubmitIfTapLengthMatches`.
- Only `remove_last` and `backtrack` are genuinely ambiguous: a tap removes tiles, while a swipe starting there carries on from that tile.

**Suggested change:**
1. For `add`, `new_chain` and `clear`: **apply them straight away on `pointerdown`** (the tile lights up instantly). Leave the tap-submit check until release, exactly as now.
2. For `remove_last` and `backtrack`: keep the 12 px wait. Use the `onPendingActionChanged` callback that is emitted but never used (`InputManager.ts:178`) to show a subtle `data-pressed` state, for example a slight brighten, until the gesture resolves.
3. **Watch `pointercancel` inside the pending window.**
   - **Today:** GameView calls `clearChain()` and then `onPointerUp(0)` (`GameView.ts:722-725`). The gesture is still pending, so it's resolved as a tap and the touched tile ends up as a fresh one-tile chain.
   - **With the instant add:** that same cancel would clear the tile already added, and it would count as an abandoned chain, which is a new mistake.
   - **Fix:** while pending, handle the cancel so it ends in today's state: the old chain cleared, and the touched tile alone. Then check that the mistake count is unchanged.
4. Optional: scale the threshold to the tile pitch (about `0.15 × pitch`, which is ≈ 12 px on a phone) so it feels the same on tablets.

The effect: an empty-chain start, adding a neighbouring tile, starting a new chain, and tapping outside all light up instantly. Only tapping or swiping from a tile already in the chain keeps the short wait. The tap/swipe split and how mistakes are counted stay the same. It's about 20 lines in `InputManager`, plus the cancel handling.
